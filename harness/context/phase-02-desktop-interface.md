Updated: 2026-11-08. The owner authorized Phase 2 and selected choices `1A, 2A, 3A` in `harness/decision-log.md`. Published commit `07391f375b56214233ac360a4a30b440f3fef4d0` met the local criteria and hosted three-system CI gate. Phases 3–7 remain locked.

## Implemented boundary

- `src/loansim/gui/` provides a Polish single-scenario form, lockable and explained derived values, inline validation, fixed/periodic/variable rate input, selected overpayments and charges, results, history controls, and a Qt balance chart with a numeric table. User colors appear in the chart. Calculation and SQLite tasks use `QThreadPool`; the GUI contains no repayment formulas.
- `src/loansim/data/` stores an allowlisted JSON snapshot of original form state, derived provenance, validated core inputs, and the complete result. Decimal and date values round-trip without floats. SQLite schema version 2 migrates version 1 in a transaction, preserves records, records engine version, and checks snapshot SHA-256 before reopening. Writes are atomic; copying creates a new ID; deletion and replacement of unsaved form state require explicit confirmation.
- Reopened results retain their stored engine version and are not silently recalculated. Payment rows identify rate source and show future constant-rate periods as assumptions. The results label the effective rate as simplified and explicitly separate it from RRSO.
- Documentation updates record the owner decisions and local verification. The previously reviewed SessionStart script was not changed; its advisory Phase 2 lock wording is stale.

A new read-only audit identified three additional defects. Resaving an unchanged result from engine `0.0.9` changed its stored engine version to `0.1.0` without recalculation. When two history-open requests overlapped, completion of the first could suppress the later user request. A saved snapshot with incomplete original form state raised `KeyError` during restoration and left the current form partially replaced. The owner requested the necessary Phase 2 corrections.

Three new offscreen workflow regressions first failed for exactly those behaviors (`3 failed, 5 deselected`, exit 1).
